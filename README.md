# ShareFund – צד הלקוח (React)

האתר של ShareFund: ניהול קופה משותפת לקבוצה. כל חבר מפקיד ומושך, ורואה את יתרת הקופה ואת היתרה שלו.
המנהל מנהל את החברים, רושם פעולות לכמה חברים יחד ושולח הודעות.

- **האתר מדבר עם השרת:** https://sharefund-server.onrender.com/api
- **תיעוד ה-API (Swagger):** https://sharefund-server.onrender.com/api-docs

## הטכנולוגיות

| מה | ספרייה |
| --- | --- |
| ממשק | React 19 + TypeScript |
| בנייה והרצה | Vite |
| ניווט בין עמודים | React Router |
| טפסים וולידציה | React Hook Form (כולל `useFieldArray` ביצירת קבוצה) |
| נתונים מהשרת | TanStack React Query |
| בקשות לשרת | axios |
| עיצוב | Tailwind CSS 4 |

## הרצה במחשב

```
npm install
npm run dev
```

ופותחים את http://localhost:5173.

כתובת השרת נמצאת בקובץ `.env`:

```
VITE_API_URL=https://sharefund-server.onrender.com/api
```

פקודות נוספות: `npm run build` (בנייה לתיקייה `dist`, כולל בדיקת TypeScript), `npm run lint` (בדיקת הקוד).

## איך זה עובד

- **התחברות:** אחרי כניסה השרת מחזיר טוקן (JWT). הוא נשמר ב-`localStorage`, ו-axios מוסיף אותו לכל בקשה
  בכותרת `Authorization`. בתשובת 401 הטוקן נמחק ועוברים לעמוד הכניסה.
- **רענון הדף:** בטעינה, אם יש טוקן שמור, קוראים ל-`GET /auth/me` ומשחזרים את המשתמש.
- **סיסמה זמנית:** משתמש עם `mustChangePassword` מועבר לשינוי סיסמה מכל עמוד.
- **הרשאות:** התפקיד (מנהל / חבר) מגיע מהשרת לכל קבוצה. האתר מסתיר כפתורים לפי התפקיד,
  אבל ההגנה האמיתית בשרת: חבר שישלח בקשה של מנהל יקבל 403.
- **נתונים מהשרת:** React Query שומר את התשובות. אחרי כל פעולה (הפקדה, הוספת חבר וכו') מרעננים
  את הנתונים שהשתנו עם `invalidateQueries`, ולא מעדכנים מערכים ידנית.

## העלאה ל-Render

הדרך הקצרה: מעלים את התיקייה למאגר ב-GitHub, וב-Render בוחרים **New ← Blueprint** ואת המאגר.
הקובץ `render.yaml` מגדיר הכול: פקודת הבנייה, תיקיית `dist`, כתובת השרת, וכלל Rewrite לכל הנתיבים.

אחרי ההעלאה מעדכנים בשרת (`sharefund-server` ב-Render) את `CORS_ORIGIN` לכתובת של האתר,
למשל: `https://sharefund-client.onrender.com,http://localhost:5173`
