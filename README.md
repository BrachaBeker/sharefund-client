# ShareFund – צד הלקוח (React)

ShareFund מנהל קופה משותפת של קבוצה (ועד כיתה, טיול, חוג): כל חבר מפקיד ומושך, ורואה את יתרת הקופה
ואת היתרה האישית שלו. המנהל מנהל את החברים, רושם פעולות לכמה חברים יחד ושולח הודעות.

## משתמשי דמו

בעמוד הכניסה יש כפתור **כניסה מהירה** לכל משתמש, ואפשר גם להקליד את הפרטים:

| שם | מייל | סיסמה | קופת ועד הכיתה | טיול משפחתי |
| --- | --- | --- | --- | --- |
| מנהל דמו | `123@gmail.com` | `123123` | מנהל | חבר |
| חבר דמו 1 | `111@gmail.com` | `111111` | חבר | מנהל |
| חבר דמו 2 | `222@gmail.com` | `222222` | חבר | – |
| חבר דמו 3 | `333@gmail.com` | `333333` | חבר | חבר (בחוב) |

- **מנהל דמו / חבר דמו 1:** שתי קבוצות, ותפקיד שונה בכל אחת. אחרי הכניסה מגיעים לבחירת קבוצה.
- **חבר דמו 2:** קבוצה אחת בלבד, ולכן אחרי הכניסה מגיעים ישר לאזור האישי.
- **טיול משפחתי** במינוס (הוצא יותר ממה שהופקד), כדי לראות את מצב החוב בקופה.
- בכל הקבוצות יש הפקדות, משיכות (אישיות ומשותפות), רישום מרוכז והודעות.

## איך זה עובד

### התחברות והרשאות

1. בעמוד הכניסה נשלחים לשרת המייל והסיסמה: `POST /api/auth/login`.
2. השרת בודק את הסיסמה (מוצפנת ב-bcrypt) ומחזיר **טוקן JWT** ואת פרטי המשתמש.
3. הטוקן נשמר ב-`sessionStorage`, ו-axios מוסיף אותו לכל בקשה בכותרת `Authorization: Bearer ...`.
   `sessionStorage` נמחק כשסוגרים את הלשונית, כך שבמחשב משותף המשתמש הבא לא נשאר מחובר.
4. ברענון הדף האתר שולח `GET /api/auth/me` עם הטוקן השמור ומשחזר את המשתמש.
5. `ProtectedRoute` לא נותן להיכנס לעמודים הפנימיים בלי משתמש מחובר, ומשתמש עם סיסמה זמנית מועבר לשינוי סיסמה.
6. התפקיד (מנהל / חבר) מגיע מהשרת בנפרד לכל קבוצה. האתר מסתיר כפתורים לפי התפקיד,
   אבל ההגנה האמיתית בשרת: בקשה של חבר לפעולת מנהל מקבלת 403, וטוקן חסר או פג תוקף מקבל 401
   (ואז האתר מוחק את הטוקן ומעביר לכניסה).

### איך המידע נשמר

- **במסד הנתונים (PostgreSQL בשרת):** משתמשים, קבוצות, שיוך לקבוצה עם תפקיד ויתרה, תנועות והודעות.
  הסכומים נשמרים באגורות (מספר שלם), כדי שלא יהיו טעויות עיגול.
- **בדפדפן:** רק הטוקן, ב-`sessionStorage`.
- **בזיכרון של האתר:** React Query שומר את התשובות מהשרת. אחרי כל פעולה (הפקדה, הוספת חבר וכו')
  הוא מרענן את הנתונים שהשתנו עם `invalidateQueries`. בהתנתקות המטמון נמחק.

### מה נשלח לשרת ומה חוזר

| פעולה | נשלח | חוזר |
| --- | --- | --- |
| כניסה | `{ email, password }` | `{ token, user }` |
| הקבוצות שלי | – | `{ groups: [{ id, name, role, myBalance, isActive }] }` |
| אזור אישי | – | `{ group: { fundBalance, totalDeposited, myBalance, managerName, membersCount, ... } }` |
| הפקדה / משיכה | `{ type, amount, category, note, isShared }` | `{ transaction }` |
| רישום מרוכז | `{ type, category, note, items: [{ userId, amount }] }` | `{ transactions }` |
| היסטוריה | סינון בכתובת: `?search=&type=&category=&from=&to=&sort=&page=` | `{ summary, page, pageSize, total, items }` |
| עריכת תנועה | `{ category, note }` | `{ transaction }` |
| הוספת חבר | `{ name, email, password }` | `{ member }` |
| שליחת הודעה | `{ content, toAll }` או `{ content, recipientIds }` | `{ message }` |

שגיאה חוזרת תמיד באותו מבנה: `{ error: { code, message } }`, וההודעה בעברית מוצגת כמו שהיא.
הרשימה המלאה ב-Swagger.

## מבנה הקוד

| תיקייה | מה יש בה |
| --- | --- |
| `src/pages/` | עמוד לכל נתיב: דף הבית, כניסה, שינוי סיסמה, יצירת קבוצה, בחירת קבוצה, אזור אישי, חברים, היסטוריה, הודעות |
| `src/components/` | חלקים שחוזרים בכמה עמודים: Header, הקופה, טופס הפקדה ומשיכה, רישום מרוכז, חלונות אישור ועריכה |
| `src/components/ui/` | אבני הבניין של העיצוב: שדה בטופס, הודעה, חלון קופץ, כותרות, אריח צבעוני, הופעה בגלילה, מצבי טעינה / שגיאה / ריק, סמלים |
| `src/routes/` | הנתיבים, הנתיב המוגן, ו-`GroupLayout` שטוען את הקבוצה פעם אחת לכל עמודי הקבוצה |
| `src/context/` | המשתמש המחובר (`AuthProvider` ו-`useAuth`) |
| `src/hooks/` | hooks משותפים: הקבוצה הנוכחית, רשימת החברים, חיפוש עם השהייה, הודעות שלא נקראו, מספר רץ, גלילה |
| `src/services/` | `api.ts` – כל הקריאות לשרת. `queryKeys.ts` – כל המפתחות של React Query במקום אחד |
| `src/types/` | הטיפוסים של TypeScript, לפי מה שהשרת מחזיר |
| `src/utils/` | עיצוב סכומים ותאריכים, שמות בעברית, כללי ולידציה, הודעות שגיאה, משתמשי הדמו, צבעים |

- **State ו-Props:** כל עמוד מחזיק את המצב שלו (סינון, חלון פתוח) ומעביר לקומפוננטות רק את מה שהן צריכות.
  נתונים מהשרת לא נשמרים ב-`useState` אלא ב-React Query.
- **Hooks:** `useAuth`, `useCurrentGroup`, `useMembers`, `useDebouncedValue`, `useUnreadCount`, `useCountUp`, `useScrolled`, ו-hooks של React Query ו-React Hook Form.
- **Routing:** עמודי הקבוצה מקוננים תחת `/group/:id`, ו-`GroupLayout` מעביר להם את הקבוצה עם `Outlet`.

## הרצה במחשב

```
npm install
npm run dev
```

ופותחים את http://localhost:5173. כתובת השרת נמצאת בקובץ `.env`:

```
VITE_API_URL=https://sharefund-server.onrender.com/api
```

פקודות נוספות: `npm run build` (בנייה לתיקייה `dist`, כולל בדיקת TypeScript), `npm run lint` (בדיקת הקוד).

## העלאה ל-Render

ב-Render בוחרים **New ← Blueprint** ואת המאגר. הקובץ `render.yaml` מגדיר הכול: פקודת הבנייה,
תיקיית `dist`, כתובת השרת, וכלל Rewrite שמחזיר את `index.html` לכל נתיב (כדי שרענון באמצע עמוד יעבוד).
בשרת מגדירים את `CORS_ORIGIN` לכתובת האתר.
